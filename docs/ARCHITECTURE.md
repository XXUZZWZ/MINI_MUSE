# MinMuse 技术结构

## 最小闭环

1. 定时器启动 CLI。
2. IMAP 客户端以只读模式搜寻未读邮件，用 `BODY.PEEK[]` 取邮件，避免改变已读状态。
3. 解析发件人、主题、日期和纯文本正文；忽略附件与 HTML，限制消息数和正文长度。
4. 分类器/LLM 为每封邮件产出简短摘要、类别、是否需要处理及建议动作。
5. 程序将原邮件元数据与整理结果写入本地 JSON，并生成便于阅读的 Markdown 日报。
6. 默认只预览。只有启用发送开关并显式传入 `--send`，才通过 SMTP 把日报发回认证账号自己的邮箱。
7. SMTP 成功后才把本次邮件的哈希 ID 记入本地账本；dry-run 不写账本，以便用户预览后再正式发送。

## 数据边界

```text
邮箱凭据 (.env) ──────────────┐
收件箱 ── IMAP READONLY ──> MinMuse ── SMTP ──> 同一邮箱
                         │
                         ├── 本地 Markdown 日报
                         └── 本地 JSON 审计记录
```

未配置 LLM 时走离线规则，便于离线演示。配置 OpenAI-compatible endpoint 后，邮件正文会发送到该模型服务；要保持本地处理，请指向本机模型服务。

## 为什么第一版不自动回复

收件箱内容可能包含误导性指令。MinMuse 把邮件正文当作待分析文本，不把它当成工具命令；第一版只自动发送汇总给账号所有者，不向外部发件人回信。这样仍完整展示“定时触发、读取信息、模型整理、邮件外发”的 agent 闭环，同时把外部沟通保留给人确认。
